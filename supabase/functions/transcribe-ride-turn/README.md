# Guided scoring (foreground Foundation Phase 1 pilot)

Use a fresh isolated Supabase project only. Apply `schema.sql`, `ride_drafts.sql`, then `guided_voice.sql`. Do not apply these files to the production project or the current Cloudflare preview backend. For ElevenLabs readback, apply the separate additive migration and configure the [readback function](../speak-ride-prompt/README.md). The scoring function uses the existing facility voice flag.

Required backend-only environment values when a separately authorized staging setup is ready:

- `SUPABASE_URL`, `SUPABASE_ANON_KEY` (normally supplied by Supabase)
- `OPENROUTER_API_KEY` for both OpenAI transcription and required Jev interpretation; server-side only, never a `VITE_` variable. Direct-provider `OPENAI_API_KEY` / `TYPESAFE_API_KEY` are not read or used as fallbacks.
- `TQA_VOICE_ALLOWED_ORIGINS`: explicit comma-separated origins, no wildcard

## One question at a time

The conversation asks one Phase 1 Foundation question and offers inline score buttons and a text box. Written values support digits, number words, plus/minus, and positive/negative. Bare written numbers from 1 through 3 are positive. A complete typed or tapped score bypasses Jev and records directly. Invalid written input keeps the current question open.

The mic button controls both the foreground microphone and [ElevenLabs readback](../speak-ride-prompt/README.md). Speech detection pauses while readback plays and while an answer is processed or saved. Muting, leaving or backgrounding the app releases the microphone. Returning to the active call can reopen it when the browser permits. Before accepting an answer, `bind_guided_turn` locks the trainer-owned draft, checks version, facility, program, and current question, snapshots the ordered Foundation questions on first use, and binds a unique turn UUID. Starting another turn supersedes the previous one.
Browser noise suppression and echo cancellation are requested where available. A speech-band filter and local voice activity gate keep a short in-memory lead-in, finish when speech pauses, and discard silence and sustained loud input. Only detected answers are uploaded. The browser sends bounded 16 kHz mono PCM WAV answers. The Edge Function retains support for older clients and enforces the existing size limit. The Edge Function verifies Supabase Auth, validates the exact bound draft/question/version/turn as that user, and rate-limits requests. OpenRouter forwards the audio-only multipart request to OpenAI and the bounded transcript-only System One request to TypeSafe: no draft, facility, horse, trainer, question IDs, bearer tokens, names, record metadata or rubric records are added to the request. Trainers should answer a **bare signed rating**, e.g. “minus two”, “plus one”, “zero”, optionally prefixed with “score”; avoid names or record details in speech. User-spoken material is necessarily part of the transcript and is sent to the provider. Audio/transcripts are neither logged nor stored by this app; OpenRouter and downstream provider handling is governed by their respective terms.

Jev interprets a single `choice` question over exactly `minus_three`, `minus_two`, `minus_one`, `zero`, `plus_one`, `plus_two`, `plus_three`, and `needs_clarification`. It never selects a rubric question. Named metrics, unsigned nonzero numbers, conflicting scores, no explicit score, unrelated speech, and qualitative descriptions must clarify. The decision model is pinned to OpenRouter `typesafe/jev-1.14`; its documented canonical response ID `typesafe/jev-1.14-20261014` is also accepted. No moving `latest` aliases or other decision models are accepted. The endpoint is fixed to `https://openrouter.ai/api/v1/systemone` in `jev.ts`. Audio uses `openai/gpt-transcribe` at `https://openrouter.ai/api/v1/audio/transcriptions` with multipart `file`, `model`, and `response_format=json`. Both adapters use the same backend-only `OPENROUTER_API_KEY`; no direct-provider fallback or record identifiers are sent. Output model/type/choice IDs/probability distribution are validated. Confidence and selected probability must both reach 0.90, an intentionally conservative pilot gate, **not a validated accuracy guarantee**. Outages/malformed output fail closed without provider retries.

The Edge Function rechecks the binding after interpretation to reject stale results. The app records a clear Jev score into the draft immediately. Uncertainty keeps the same question open and asks for clarification. The Edge Function retains the earlier typed and spoken-confirmation request formats for clients built before the redesign. The trainer's authenticated client saves through `confirm_guided_score`.

After Foundation, a bounded choice recording uses `temperament_audio` and the draft ID, version, and turn ID. Supabase checks the offer before and after speech-to-text. An exact spoken choice like “now” or “later” is parsed directly. Starting Temperament appends the unanswered Temperament questions to the same saved draft. Later returns to review and leaves the offer available on resume.

Recording a score validates the still-active turn and version, persists all current draft fields and the signed rating, advances the cursor, increments version and records the idempotency receipt in one database transaction. Failed writes roll back both score and cursor. An exact retry cannot advance twice and returns the current authorized draft rather than replaying an obsolete cursor; altered payload reuse is rejected. Reload/resume restores the server cursor. Manual draft saves change the version and invalidate in-flight turns. Recorded draft ratings stay out of ride history until the separate explicit **Save ride** finalization. Facility removal/suspension and trainer isolation reuse the existing locked authorization checks; helpers and turn tables are private.

## Verified and not yet verified

Node 22 app tests cover exact written score parsing, choice validation, ambiguity fixtures (mocked Jev decisions), provider failures, pre-listen binding, clarification, cancellation/background handling, late/stale responses, retry and resume sequencing. Disposable PostgreSQL tests cover exact/historical duplicate confirmations, failed receipt rollback, durable score/cursor, full sequence, explicit final save and permissions; existing facility/ride suites remain included. `deno check` validates the Edge Function entrypoint. These are mock/synthetic checks, not evidence of live provider semantic accuracy.

Before enabling any staging pilot: verify isolated preview/backend configuration; deploy matching SQL and Edge Function only with separate authorization; verify hosted Auth, actual provider model access/latency/ambiguity handling with synthetic speech, and physical iPhone Safari microphone access, speech detection and readback with ambient barn noise. No live paid-provider calls, credentials, real iPhone/headset, or production persistence were tested in this change. Automatic listening requires a foreground chat and explicit microphone activation. It does not identify the speaker and background conversation can still be picked up.

- [OpenRouter transcription schema](https://openrouter.ai/docs/api/api-reference/stt/create-transcription): OpenAI-compatible multipart upload and JSON transcript.
- [OpenRouter model catalog](https://openrouter.ai/api/v1/models?output_modalities=decisions,transcription): verified `typesafe/jev-1.14` and `openai/gpt-transcribe`; no authenticated inference was called.
- [TypeSafe Choice](https://docs.typesafe.ai/primitives/choice) and [confidence](https://docs.typesafe.ai/confidence) retain the original closed-choice scoring semantics.
