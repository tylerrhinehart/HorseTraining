# Guided scoring (foreground Foundation Phase 1 pilot)

Use a fresh isolated Supabase project only. Apply `schema.sql`, `ride_drafts.sql`, then `guided_voice.sql`. Do not apply these files to the production project or the current Cloudflare preview backend. Function updates do not change the database schema, provision provider credentials, or enable voice. Existing facility-aware installations only need the updated function and shared OpenRouter secret.

Required backend-only environment values when a separately authorized staging setup is ready:

- `SUPABASE_URL`, `SUPABASE_ANON_KEY` (normally supplied by Supabase)
- `OPENROUTER_API_KEY` for both OpenAI transcription and required Jev interpretation; server-side only, never a `VITE_` variable. Direct-provider `OPENAI_API_KEY` / `TYPESAFE_API_KEY` are not read or used as fallbacks.
- `TQA_VOICE_ALLOWED_ORIGINS`: explicit comma-separated origins, no wildcard

## One question, one confirmed answer

The conversation displays the current Phase 1 Foundation rubric question and can read it using an available **local** browser voice. Trainers can speak, type a signed score, or choose one directly. Nothing listens automatically. Before accepting an answer, `bind_guided_turn` locks the trainer-owned draft, checks version/facility/program/current question, snapshots ordered Foundation question IDs on first use, and binds a unique turn UUID. Starting another turn supersedes the previous one. No score or cursor advances here.

A clip lasts at most eight seconds and 512 KiB. The Edge Function verifies Supabase Auth, validates the exact bound draft/question/version/turn as that user, and rate-limits requests. OpenRouter forwards the audio-only multipart request to OpenAI and the bounded transcript-only System One request to TypeSafe: no draft, facility, horse, trainer, question IDs, bearer tokens, names, record metadata or rubric records are added to the request. Trainers should answer a **bare signed rating**, e.g. “minus two”, “plus one”, “zero”, optionally prefixed with “score”; avoid names or record details in speech. User-spoken material is necessarily part of the transcript and is sent to the provider. Audio/transcripts are neither logged nor stored by this app; OpenRouter and downstream provider handling is governed by their respective terms.

Jev interprets a single `choice` question over exactly `minus_three`, `minus_two`, `minus_one`, `zero`, `plus_one`, `plus_two`, `plus_three`, and `needs_clarification`. It never selects a rubric question. Named metrics, unsigned nonzero numbers, conflicting scores, no explicit score, unrelated speech, and qualitative descriptions must clarify. There is **no alias/transcript parser fallback**, no qualitative grading and no automatic confirmation. The decision model is pinned to OpenRouter `typesafe/jev-1.14`; its documented canonical response ID `typesafe/jev-1.14-20261014` is also accepted. No moving `latest` aliases or other decision models are accepted. The endpoint is fixed to `https://openrouter.ai/api/v1/systemone` in `jev.ts`. Audio uses `openai/gpt-transcribe` at `https://openrouter.ai/api/v1/audio/transcriptions` with multipart `file`, `model`, and `response_format=json`. Both adapters use the same backend-only `OPENROUTER_API_KEY`; no direct-provider fallback or record identifiers are sent. Output model/type/choice IDs/probability distribution are validated. Confidence and selected probability must both reach 0.90, an intentionally conservative pilot gate, **not a validated accuracy guarantee**. Outages/malformed output fail closed without provider retries.

Typed answers use the same authenticated, rate-limited binding and Jev decision with no audio transcription. The Edge Function rechecks the binding after interpretation to reject results that became stale while providers were running. Clarification/failure leaves the same question and writes no rating. The conversation displays the proposed signed score and requires **Confirm score** or **Try again**. Spoken answers also receive local readback of the rubric and proposed score when a local voice is available. The pick-a-score control bypasses inference but requires the same confirmation. Only authenticated trainer confirmation calls `confirm_guided_score`; the model/Edge Function has no scoring write authority. This RPC is intentionally a trainer-editable scoring endpoint, not a cryptographically attested model output.

Confirmation validates the still-active turn/version, persists all current draft fields and the signed rating, advances the cursor, increments version and records the idempotency receipt in one database transaction. Failed writes roll back both score and cursor. An exact retry cannot advance twice and returns the current authorized draft rather than replaying an obsolete cursor; altered payload reuse is rejected. Reload/resume restores the server cursor. Manual draft saves change the version and invalidate in-flight turns. Confirmed draft ratings stay out of ride history until the separate explicit **Save ride** finalization. Facility removal/suspension and trainer isolation reuse the existing locked authorization checks; helpers and turn tables are private.

## Verified and not yet verified

Node 22 app tests cover the typed provider contract, choice validation, ambiguity fixtures (mocked Jev decisions), provider failures, pre-listen binding, clarification, cancellation/background handling, late/stale responses, retry and resume sequencing. Disposable PostgreSQL tests cover exact/historical duplicate confirmations, failed receipt rollback, durable score/cursor, full sequence, explicit final save and permissions; existing facility/ride suites remain included. `deno check` validates the Edge Function entrypoint. These are mock/synthetic checks, not evidence of live provider semantic accuracy.

Before enabling any staging pilot: verify isolated preview/backend configuration; deploy matching SQL and Edge Function only with separate authorization; verify hosted Auth, actual provider model access/latency/ambiguity handling with synthetic speech, and physical iPhone Safari microphone/readback/repeated-recording behavior. No live paid-provider calls, credentials, real iPhone/headset, or production persistence were tested in this change. Stay foreground push-to-talk; background/lock-screen or hands-free riding is not supported.

## Official contract references (checked 2026-11-22)

- [OpenRouter System One schema](https://openrouter.ai/docs/api/api-reference/systemone/submit-a-system-one-request): TypeSafe-compatible request/response and canonical model IDs.
- [OpenRouter TypeSafe SDK guide](https://openrouter.ai/docs/guides/community/typesafe-sdk): `https://openrouter.ai/api/v1/systemone` and OpenRouter bearer authentication.
- [OpenRouter transcription schema](https://openrouter.ai/docs/api/api-reference/stt/create-transcription): OpenAI-compatible multipart upload and JSON transcript.
- [OpenRouter model catalog](https://openrouter.ai/api/v1/models?output_modalities=decisions,transcription): verified `typesafe/jev-1.14` and `openai/gpt-transcribe`; no authenticated inference was called.
- [TypeSafe Choice](https://docs.typesafe.ai/primitives/choice) and [confidence](https://docs.typesafe.ai/confidence) retain the original closed-choice scoring semantics.
